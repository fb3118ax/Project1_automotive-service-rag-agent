# BMW RAG Agent — Frontend Development Summary

## Project Overview

A production-grade RAG (Retrieval-Augmented Generation) agent for BMW service manual queries. The agent supports two user modes (owner/technician), multi-turn conversation, confidence scoring, guardrails, and query expansion. Deployed on Render, backed by ChromaDB vector store, orchestrated with LangGraph.

---

## Live API

- **Base URL:** `https://project1-automotive-service-rag-agent.onrender.com`
- **Method:** `POST /query`
- **Content-Type:** `application/json`

---

## API Contract

### Request
```json
{
  "query": "what oil should I use",
  "session_id": "uuid-generated-by-client",
  "user_type": "owner"
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `query` | string | yes | Max 500 chars. Empty queries are blocked by guardrail. |
| `session_id` | string | yes | UUID generated by client. Same session_id = same conversation history. |
| `user_type` | string | yes | `"owner"` or `"technician"` |

### Response
```json
{
  "answer": "For your BMW petrol engine...",
  "citations": [
    {
      "page": 417,
      "section": "page_417",
      "source": "bmw_manual.pdf"
    }
  ],
  "confidence_score": 0.6297,
  "guardrail_response": ""
}
```

| Field | Type | Notes |
|-------|------|-------|
| `answer` | string | The agent's response. If guardrail triggered, contains the safe message. |
| `citations` | array | Pages from manual that were used. Empty if guardrail blocked or no results. |
| `confidence_score` | float | 0.0–1.0. < 0.4 = good match, 0.4–0.7 = acceptable, > 0.7 = poor match (caveat appended). 0.0 = guardrail blocked. |
| `guardrail_response` | string | Non-empty only when guardrail triggered. Otherwise empty string `""`. |

## Frontend Logic

### Session Management
- Generate a UUID when the chat session starts: `crypto.randomUUID()`
- Store it in component state or `sessionStorage`
- Pass it with every `/query` call
- Do NOT expose it to the user

### Detecting Guardrail Blocks
```javascript
if (response.guardrail_response !== "") {
  // show guardrail_response as the message, not answer
  // do not add to conversation history
} else {
  // show answer normally
  // add to conversation history display
}
```

### Confidence Score Display
```javascript
if (confidence_score < 0.4) {
  // show green indicator — high confidence
} else if (confidence_score <= 0.7) {
  // show amber indicator — acceptable
} else {
  // show red indicator — low confidence
  // answer already contains ⚠️ caveat from agent
}
```

### User Type Toggle
- Simple toggle or radio: `Owner` / `Technician`
- Affects response style server-side (simple language vs technical specs)
- Store in component state, send with every request

## UI Components Needed

### Core
1. **Chat interface** — message bubbles, user/assistant distinction
2. **Input bar** — text input + send button, max 500 char hint
3. **User type toggle** — Owner / Technician radio/toggle
4. **Loading state** — spinner or typing indicator (agent takes 4–12s)

### Per Message
5. **Confidence badge** — green/amber/red pill on assistant messages
6. **Citations panel** — collapsible list of page references below answer
7. **Guardrail indicator** — subtle visual distinction for blocked messages

### Optional
8. **New conversation button** — generates new session_id, clears display
9. **User type label** — show current mode in header

## Guardrail Behaviour (what to expect)

| Trigger | `guardrail_response` | `answer` | `confidence_score` |
|---------|---------------------|----------|-------------------|
| Empty query | "Please Enter a valid input" | same | 0.0 |
| Query > 500 chars | "Query is too long..." | same | 0.0 |
| Injection pattern | "Invalid input detected." | same | 0.0 |
| Profanity | "Only to answer service related questions" | same | 0.0 |
| Normal query | `""` | actual answer | 0.0–1.0 |
| No manual match | `""` | fallback message | 0.0 |

## Known Limitations (for frontend handling)

- **Cold start delay** — Render free tier spins down after inactivity. First request after idle can take 30–60s. Show a "waking up..." message if response takes > 5s.
- **Session persistence** — Sessions are in-memory on Render. A redeploy resets all sessions. Handle gracefully — if history seems lost, prompt user to start a new conversation.
- **No image serving** — Manual images are not served via URL yet. Do not build image display UI until that feature is available.
- **Citations are page-level only** — `section` field is always `"page_XX"`, not a semantic section name. Display as "Page 417" not the section value.

## Recommended Stack

Given your background and the project constraints, **Streamlit** is the fastest path to a working frontend:
- Python only — no React/JS needed
- Session state via `st.session_state`
- Deploys free on Streamlit Cloud
- 1–2 days to build

If you want a more polished look: **React + Tailwind** hosted on Vercel. Longer build but more control over UI.
